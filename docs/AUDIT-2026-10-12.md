## 二、P0 修复清单（7 项）

### 1. Agent 工具调用链路从未接通（README 实现状态 #1）

**根因**：`agent/nodes.py` 调 `acompletion` 时不传 `tools=`，全仓 `tools=` 零命中。
`nodes.py` 里解析 `tool_calls` 的分支永不可达，模型只能输出散文，
「多步推理 + 工具调用」在生产中完全不生效。

**修复**：

| 文件 | 修复 |
|---|---|
| `agent/tools.py:73` | `ToolDefinition.to_openai_tool()` — 复用现有 JSON Schema，不维护第二份 |
| `agent/tools.py:108` | `ToolRegistry.openai_tools()` |
| `agent/nodes.py:47` | `reason_node(state, registry)` — 下发 `tools=` + `tool_choice="auto"` |
| `agent/graph.py:78` | `partial(reason_node, registry=self._registry)` 绑定实例 registry |
| `config/settings.py` | `AgentConfig.tool_calling` 开关（兼容不支持 function calling 的私有端点） |

**顺带修的两个真实缺陷**：

- 一轮多个 `tool_calls` 原本只执行第一个，但 assistant 消息里保留全部 → 服务端报 400。
  改为 `pending_tool_calls` 列表，全部执行并逐个回填配对的 `tool` 消息。
- `ToolCall` 补 `tool_call_id`；缺 id 时整体退回「纯文本 + user 角色观测」，
  避免半截 `tool_calls` 无法配对。

**验证**：`tests/test_wiring_p0.py` 断言 `m.await_args.kwargs["tools"]` 里确实有
`shell` / `send_message` / `knowledge_search` 三项，且 schema 为 OpenAI function 形态。

### 2. 三个模块生产零挂载（README 实现状态 #6）

`__main__.py` 调 `create_dashboard_app(...)` 时没传 `agent=` / `experiment_engine=`，
而 dashboard_api 是靠 `if xxx is not None` 决定是否注册路由。后果：

- `/api/stream/chat`、`/api/sessions/{chat_id}/stream` 不存在 → SSE 流式不可用
- `/api/experiments*` 全部 404 → 前端 `api.ts` 6 处请求必然失败
- `auth.enabled` 即使打开也不会挂 `/auth/*`

**修复**：新增 `seat/` `workflow/` `mcp/` 三组挂载（此前这三块**零挂载**，
合计约 2100 行生产不可达代码），并把引擎持有的组件全部透传。

### 3. MCP 工具路由无凭据校验（挂载前必须先修）

`mcp/router.py` 原本只读 `X-Miner-Permission` 头 —— 那是**权限等级不是凭据**。
任何人 `POST /v1/tools/call` 带 `X-Miner-Permission: 4` 即可执行 shell。

> 这个缺陷此前不可见，正因为该模块从未被挂载。**挂载一个没鉴权的写接口等于开后门**，
> 所以先补 `_require_admin` 再挂载。

### 4. `/metrics` 无鉴权（README 实现状态 #7）

匿名 `GET /metrics` 可读到全部内部端点名与状态码分布。

**修复**：新增 `MetricsConfig.scrape_token`（未配置回退 admin_token），
未配置凭据时 fail-closed 返回 503。

### 5. 权限等级来源是进程级全局常量（README 实现状态 #4）

`__main__.py` 写死 `_PERMISSION_LEVEL = 1`，pipeline 的 `current_permission`
形参标着 `# noqa: ARG002` 从不使用 → 不存在按用户分级。

**修复**（对应「权限可以给到」）：

| 层 | 改动 |
|---|---|
| `config/settings.py` | `SecurityConfig.default_permission_level` + `permission_rules: dict[str,int]` |
| `persona/guardrails.py` | `resolve_permission_level(user_id, chat_id)` — 优先级 user > chat > `@all` > 基线 |
| `agent/state.py` | `AgentState.current_permission`（按会话携带） |
| `agent/nodes.py` | `execute_tool_node` 从 state 读权限，构造参数仅作兜底 |
| `flow/pipeline.py` | 真正使用 `current_permission` 透传给 agent |
| `__main__.py` | 每条 IM 事件按 user/chat 解析等级 |

配置示例：

```bash
LINGXI_SECURITY__PERMISSION_RULES='{"u_vip_001": 2, "wxid_abc": 0}'
```

越界值（如 9）被忽略并告警 —— 配置笔误不能把人提到红线之上。

### 6. 坐席路由挂载后裸奔（挂载引入的新风险）

`seat/router.py` 自身无鉴权，且 `/seats/metrics` 被 `/seats/{username}` 抢先匹配返回 404
（FastAPI 按注册顺序匹配）。两处一并修：`_require_admin` 作为 router 级依赖 +
静态路径前置。

### 7. `graph_store` 双向遍历断链（图谱能力名存实亡）

`MemoryItem.entities` 恒为空 → 图谱永远没有节点；
即便有节点，`add_relation` 只登记 `_adj[source]`，从实体侧反查恒为空。

**修复**：

- `memory/pipeline.py` — 实体抽取接进 `encode_and_store`，建「记忆 → 实体」边
- `memory/graph_store.py` — 邻接表双向登记，`related()` 返回边的另一端
- `recall_hybrid()` — 字面召回 + 图谱召回去重合并，生产入口改用它

> 实体抽取刻意用**可审计的词表**而非 jieba/spaCy 或 2-4 字滑窗：
> 滑窗会产出「套餐下月」「餐下月自」这类跨词边界垃圾，图谱召回退化成另一套
> 字面匹配，没有语义增益。词表命中是「宁可漏也不错」。

## 九、第四轮：PostgreSQL 后端接入 + SSE 事件流完整打通（2026-10-12 续）

把遗留项清单的 2/4 全部销号。

### PostgreSQL 后端 (src/lingxi/flow/postgres.py)

**核心矛盾**：`PostgresEscalationQueue` 等类全是 `async def`，而 `CustomerServicePipeline` 同步调用 `queue.enqueue()` / `memory.recall_hybrid()`。单测能显式 `await`，生产路径同步上下文无法 `await`。

**解法**：_AsyncRunner 后台事件循环线程（daemon），同步包装器 `SyncPostgres*` 在 `run_coroutine_threadsafe` 上跑 async 方法并阻塞取结果。

| 包装器 | 暴露接口 |
|---|---|
| `SyncPostgresTicketStore` | `create/get/save/list_active/list_idle` |
| `SyncPostgresEscalationQueue` | `enqueue/dequeue/complete/list_pending/list_claimed/pending_count/size` + **`subscribe/unsubscribe`（SSE 必需）** |
| `SyncPostgresMemoryPipeline` | `store/recall/recall_hybrid` + `graph` property |

**工厂统一入口**：`persistence_factory.create_stores(settings, graph)` 根据 `backend` 返回同步接口三件套：
- `sqlite` → `Persistent*`（原生同步）
- `postgresql` → `SyncPostgres*`
- `memory` → in-memory 实例

**图谱集成**：SQLite 后端透传 `graph=SQLiteGraphStore(...)`，PostgreSQL 暂无图谱后端（传 `None`），记为已知限制。
